# Qipli

## 1. Краткое описание

Qipli — бесплатное open-source приложение для macOS, которое локально хранит историю буфера обмена за последние 30 дней и помогает последовательно переносить серии текстовых значений между приложениями. Его ключевая возможность — визуальный Paste Stack: управляемая очередь копирований для последовательной вставки через обычное сочетание `⌘V`.

## 2. Цель проекта

Создать полезный инструмент для специалистов, которые регулярно переносят множество значений между окнами, вкладками, формами или таблицами. Qipli должен сокращать количество переключений между источником и местом назначения, ускорять такой перенос и позволять восстановиться после ошибочной вставки без повторного поиска данных в исходном приложении.

## 3. Проблема и текущая ситуация

Сегодня пользователь обычно переносит данные по одному: открывает источник, копирует значение, переключается в другое окно или вкладку, вставляет его в нужное поле, возвращается к источнику и повторяет цикл. При большом количестве данных постоянные переключения занимают время, нарушают концентрацию и увеличивают вероятность вставить значение не в то поле.

Обычная история буфера обмена помогает вернуть ранее скопированное значение, но не организует серию копирований в заранее подготовленную последовательность. Кроме того, при быстрой работе два значения могут случайно попасть в одно поле. Если использованные элементы сразу исчезают из очереди, исправить такую ошибку неудобно.

## 4. Целевая аудитория

### Основная аудитория

Разработчики, которые переносят серии значений, ссылок или фрагментов кода между файлами, инструментами, браузерными вкладками и формами.

### Вторичная аудитория

- Бизнес-аналитики и специалисты по данным, работающие с наборами значений, таблицами и формами.
- Тестировщики, которым приходится последовательно вводить тестовые данные в разные поля или интерфейсы.
- Другие пользователи macOS, регулярно переносящие несколько текстовых значений между приложениями.

## 5. Пользователи и роли

### Пользователь macOS

- Цель: быстрее и без потери данных переносить серии текстовых значений между приложениями, а также находить недавние копирования.
- Ключевые действия: включает Paste Stack, копирует элементы, проверяет и меняет их порядок, выбирает направление, последовательно вставляет элементы, повторно активирует ошибочно использованный элемент, ищет значения в общей истории.

Других пользовательских или административных ролей в первой версии нет.

## 6. Ценность продукта

Qipli заменяет многократный цикл «переключиться — скопировать — переключиться — вставить» двумя последовательными проходами: сначала пользователь собирает нужные значения в источнике, затем переходит в место назначения и вставляет их одно за другим.

Визуальная очередь делает предстоящий порядок понятным до начала вставки. Сохранение использованных элементов в disabled-состоянии позволяет исправить ошибку, пока стек открыт. После завершения любое значение остаётся доступным через общую 30-дневную историю.

## 7. Основные сценарии использования

### Сценарий 1: Последовательный перенос набора значений

- Участник: пользователь macOS, работающий с серией текстовых данных.
- Триггер: нужно перенести несколько значений из одного приложения, окна или вкладки в другое.
- Начальная ситуация: без Qipli каждое значение приходится копировать и вставлять отдельным циклом с переключением между источником и назначением.
- Шаги:
  1. Пользователь нажимает `⌘⇧C`.
  2. Qipli включает режим Paste Stack и показывает компактную панель поверх других приложений.
  3. Пользователь последовательно копирует текст, ссылки или код в исходном приложении.
  4. Каждое копирование добавляется в стек как отдельный элемент. Два одинаковых копирования сохраняются как два отдельных элемента.
  5. Пользователь при необходимости меняет порядок элементов и выбирает прямую или обратную последовательность вставки.
  6. Пользователь переходит в приложение назначения и нажимает обычное `⌘V` для каждого следующего поля.
  7. После каждой вставки использованный элемент остаётся в панели, но становится disabled.
  8. После вставки последнего активного элемента Qipli завершает режим и закрывает панель.
- Успешный результат: вся серия значений перенесена в нужной последовательности без повторных возвращений к источнику за каждым значением.
- Важные исключения:
  - Если значение вставлено не туда, пользователь может повторно включить соответствующий disabled-элемент. Он становится следующим на вставку, не изменяя состояния остальных элементов.
  - Если ошибка обнаружена после закрытия завершённого стека, пользователь находит значение в общей истории и вставляет его повторно.
  - Если пользователь нажимает `Esc` или закрывает незавершённый стек, режим прекращается, но собранные значения остаются в общей истории.

### Сценарий 2: Поиск и повторная вставка недавнего копирования

- Участник: пользователь macOS.
- Триггер: нужно повторно использовать значение, скопированное в течение последних 30 дней.
- Начальная ситуация: нужное значение больше не является текущим содержимым системного буфера обмена.
- Шаги:
  1. Пользователь нажимает `⌘⇧V`.
  2. Qipli открывает компактное окно истории поверх текущего приложения и переводит фокус в поиск.
  3. Пользователь вводит запрос или просматривает результаты, перемещаясь по ним стрелками.
  4. Пользователь выбирает значение и нажимает `Enter`.
  5. Qipli вставляет выбранное значение в поле, которое было активно до открытия истории.
- Успешный результат: пользователь находит и повторно вставляет нужное значение, не возвращаясь к исходному приложению.

## 8. Основной пользовательский путь

1. Пользователь устанавливает и запускает Qipli на Mac.
2. Во время обычной работы приложение локально формирует историю текстовых копирований.
3. Когда требуется перенести серию данных, пользователь включает Paste Stack через `⌘⇧C`.
4. Пользователь собирает значения, видит их в плавающей панели и при необходимости меняет порядок или направление.
5. В приложении назначения пользователь последовательно нажимает `⌘V`; Qipli показывает прогресс через состояния элементов.
6. При ошибке пользователь повторно активирует нужный элемент и вставляет его ещё раз.
7. После последней вставки стек закрывается; все скопированные значения продолжают жить в общей истории до окончания срока хранения.
8. Позже пользователь может открыть историю через `⌘⇧V`, найти значение и вставить его через `Enter`.

## 10. Основная информация продукта

### Элемент истории

- Значение: отдельное текстовое содержимое, скопированное пользователем.
- Источник: системное действие копирования в любом поддерживаемом приложении macOS.
- Использование: поиск и повторная вставка, а также формирование Paste Stack во время активного режима.
- Жизненный цикл: сохраняется локально и доступно в общей истории в течение 30 дней; закрытие или завершение стека не удаляет элемент из истории.

### Элемент Paste Stack

- Значение: отдельное копирование, добавленное в текущую очередь последовательной вставки.
- Источник: каждое новое копирование после включения режима Paste Stack.
- Использование: предпросмотр порядка, ручная перестановка и последовательная вставка.
- Жизненный цикл: сначала ожидает вставки, после вставки становится disabled, при необходимости может быть повторно активирован; после завершения или отмены стека отдельная очередь закрывается, а содержимое остаётся в общей истории.

## 11. Интеграции и внешние участники

Для первой версии внешние сервисы и человеческие участники не требуются. Продукт взаимодействует только с обычными действиями копирования и вставки в приложениях macOS; содержимое не передаётся во внешние сервисы.

## 12. Бизнес-модель и ценность для владельца

Qipli создаётся как бесплатный open-source продукт без платных тарифов. Ценность для владельца — решить собственную регулярно возникающую задачу разработчика и дать такой же инструмент другим специалистам, работающим с множеством данных.

## 13. Ограничения и важные условия

- Платформа и устройства: только macOS.
- Приватность: вся история хранится локально на текущем Mac; аккаунта, облачной передачи и синхронизации в первой версии нет.
- Чувствительные данные: первая версия не фильтрует копирования автоматически, поэтому в историю может попасть чувствительный текст.
- Срок хранения: элементы истории доступны в течение последних 30 дней.
- Типы содержимого: первая версия ограничена текстом, ссылками и кодом; файлы и медиа откладываются.
- Подключение к интернету: основной пользовательский результат не должен зависеть от внешних сервисов.

## 14. Критерии успеха

- Пользователь может собрать серию текстовых значений в одном приложении и последовательно вставить её в другом без возвращения к источнику за каждым значением.
- Пользователь может увидеть и изменить порядок элементов до вставки, а также выбрать прямую или обратную последовательность.
- Пользователь может исправить ошибочную вставку, повторно активировав использованный элемент, пока стек открыт.
- После завершения стека пользователь может найти нужное значение в общей истории и вставить его повторно.
- Пользователь может найти обычное текстовое копирование, сделанное в пределах 30-дневного срока хранения, и вставить его в активное поле.
- Основные сценарии работают без аккаунта, синхронизации и передачи содержимого внешним сервисам.

## 15. Принятые решения

- Продукт называется Qipli и создаётся как нативное приложение для macOS.
- Продукт будет бесплатным и open source.
- Основная аудитория — разработчики; вторичная — аналитики, специалисты по данным, тестировщики и другие пользователи, переносящие серии данных.
- История хранится локально за последние 30 дней.
- Первая версия поддерживает текст, ссылки и код с сохранением исходного содержимого.
- Файлы, изображения и другие медиа откладываются на будущее.
- История открывается через `⌘⇧V`; поиск доступен сразу, результаты выбираются стрелками, вставка выполняется через `Enter`.
- Paste Stack включается через `⌘⇧C` и отображается в панели поверх остальных приложений.
- В стеке одинаковые копирования являются отдельными элементами.
- Пользователь может вручную менять порядок и выбирать прямую либо обратную вставку.
- Обычное `⌘V` вставляет следующий элемент стека.
- Вставленный элемент остаётся видимым в disabled-состоянии и может быть повторно активирован как следующий на вставку.
- После последнего элемента стек автоматически закрывается; после этого повторная вставка выполняется через общую историю.
- Незавершённый стек можно закрыть через `Esc`, не удаляя собранные значения из общей истории.
- Завершённые стеки не сохраняются отдельно.
- В первой версии нет аккаунтов, синхронизации и автоматической фильтрации чувствительных данных.

## 16. Предположения

- По умолчанию Paste Stack использует прямой порядок вставки — от первого скопированного элемента к последнему. Влияние, если неверно: потребуется изменить начальное состояние выбора направления, но основной сценарий и состав первой версии сохранятся.
- Интернет не требуется для основных сценариев истории и Paste Stack. Влияние, если неверно: появится внешняя зависимость, которую нужно будет отдельно описать с точки зрения доступности и приватности.

## 17. Открытые вопросы

- Должен ли пользователь иметь возможность вручную удалить отдельное значение или немедленно очистить всю историю? Почему это важно: первая версия не фильтрует чувствительное содержимое, поэтому управление удалением может быть значимой частью контроля над локальными данными.
- Должны ли сочетания `⌘⇧C` и `⌘⇧V` быть настраиваемыми? Почему это важно: они могут конфликтовать с командами других установленных приложений, но настройка сочетаний не влияет на основную ценность продукта.
