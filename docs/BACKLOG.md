# Qipli — бэклог

Здесь хранятся наблюдения и идеи, к которым решено вернуться позже. Запись в этом файле не означает, что пункт запланирован или назначен на срез.

## BL-001 — Gentle reminder для фоновых Sparkle-проверок

- Связано с: S015, Sparkle `supportsGentleScheduledUpdateReminders`.
- Наблюдение: для menu-bar/background приложения запланированное окно Sparkle может появиться за другим активным окном, поэтому пользователь не заметит доступное обновление.
- Решение на сейчас: automatic checks остаются выключенными по умолчанию и включаются только явным opt-in.
- Следующее действие: при следующем изменении update UI добавить ненавязчивый индикатор `Update Available…` в status menu и передавать действие в стандартный Sparkle update flow.
- Ограничение: не добавлять network path, clipboard/history payload или автоматическую установку обновления.

## BL-002 — Настраиваемое положение Top Notch

- Связано с: S027, S030, D-038.
- Наблюдение: после верхней поставки пользователь хочет выбирать в Settings правый, левый или нижний край экрана и получать то же раскрытие в зеркальном направлении.
- Решение на сейчас: production поддерживает только верхнее положение; Settings не показывает неработающие варианты.
- Следующее действие: после приёмки S030 и реального использования общего History/Stack shell создать отдельный slice для edge enum, settings migration, multi-display placement и direction-aware motion.
- Ограничение: не дублировать четыре разных panel controller и не использовать hardcoded размеры notch/screen.

## BL-003 — Дополнительные разделы карточной библиотеки

- Связано с: BL-004, BL-005, S029.
- Наблюдение: пользователь обозначил History, Favorites «и так далее», но остальные назначения и их данные пока не определены.
- Решение на сейчас: отдельная полноценная библиотека не входит в активный план; дополнительные разделы не проектируются до возврата к BL-004.
- Следующее действие: добавлять новый раздел только после определения пользовательского пути, источника данных, retention/delete semantics и отдельного покрытия требований.
- Ограничение: не добавлять account, sync, telemetry, remote URL preview или новые network owners неявно.

## BL-004 — Отдельное полноразмерное окно History

- Связано с: S028, superseded D-036, D-038.
- Наблюдение: отдельное resizable окно с трёхколоночной карточной сеткой было спланировано как продолжение Top Notch, но пользователь пока не видит реального сценария, который оправдывает вторую History surface.
- Решение на сейчас: `Развернуть`, transfer query/selection/target и отдельное History window исключены из активного плана. История S028 сохранена, implementation не начинается.
- Следующее действие: возвращаться к концепции только после наблюдаемой потребности в долгом просмотре, массовой навигации или большей площади карточек, которую Top Notch не может дать.
- Ограничение: не добавлять hidden full-window state, вторую paste transaction или partial `Развернуть` control заранее.

## BL-005 — Favorites

- Связано с: S029, withdrawn D-037, BL-004.
- Наблюдение: прежний Favorites flow был частью навигации отдельного full History window. После отказа от этого окна место, пользовательский путь и retention-семантика Favorites снова не определены.
- Решение на сейчас: favorite marker, migration и navigation не входят в активный продуктовый контракт.
- Следующее действие: сначала подтвердить конкретный сценарий Favorites и решить, влияет ли marker на 30-day retention; затем заново определить presentation независимо от старого S029.
- Ограничение: не добавлять бессрочное хранение clipboard payload, отдельную копию occurrence или скрытую retention policy без нового accepted decision.
