# Qipli — продуктовый контракт

Статус: согласованный план MVP

Дата актуализации: 2026-08-06

Источник исходного замысла: [`../PROJECT_BRIEF.md`](../PROJECT_BRIEF.md)

## 1. Назначение продукта

Qipli — бесплатное open-source приложение для macOS, которое хранит локальную 30-дневную историю текстового буфера обмена и помогает переносить серии значений между приложениями с помощью визуальной очереди Paste Stack.

Основной пользователь — владелец текущей учётной записи macOS. Других ролей, аккаунтов и административного интерфейса в MVP нет.

### Проблема

При последовательном переносе нескольких значений пользователь вынужден многократно переключаться между источником и назначением. Обычная история буфера помогает найти прежнее значение, но не задаёт порядок серии и не даёт удобного восстановления после ошибочной вставки.

### Результат первой версии

Первая версия полезна, когда пользователь может собрать несколько текстовых копирований в одном приложении, проверить их порядок, вставить их по очереди в другом приложении через обычное `⌘V`, восстановить ошибочно использованный элемент и позднее найти любое сохранённое значение в локальной 30-дневной истории.

## 2. Граница MVP

### Обязательно

- нативное приложение для macOS 14 и новее;
- работающий в фоне локальный монитор текстового буфера обмена;
- история текстовых копирований за последние 30 дней;
- окно истории по `⌘⇧V`, поиск, навигация стрелками и вставка по `Enter`;
- удаление отдельной записи и немедленная логическая очистка всей истории Qipli;
- Paste Stack по `⌘⇧C` с панелью поверх других приложений;
- отдельный элемент очереди для каждого события копирования, включая одинаковый текст;
- ручное изменение порядка и прямое/обратное направление;
- последовательная вставка через обычное `⌘V`;
- видимые использованные элементы, их повторная активация и автоматическое завершение;
- отмена незавершённого стека без удаления записей из истории;
- локальная работа без аккаунта, облака, аналитики и передачи содержимого наружу;
- подписанный и notarized релиз через GitHub Releases.

### Позже

- файлы, изображения и другие медиа;
- настраиваемые глобальные сочетания клавиш;
- запуск при входе в систему;
- сохранение завершённых стеков как повторно используемых наборов.

### Не входит в MVP

- аккаунты, роли и синхронизация между устройствами;
- сервер, сетевой API, телеметрия и облачное резервное копирование;
- автоматическое распознавание паролей или чувствительных данных;
- гарантированное forensic/secure-стирание байтов с накопителя;
- Mac App Store, монетизация и платные тарифы;
- восстановление незавершённого Paste Stack после перезапуска или аварийного завершения Qipli.

## 3. Пользовательские пути

### PJ-001 — Найти и повторно вставить значение

1. Qipli уже запущен и собирает текстовые копирования локально.
2. Пользователь активирует поле назначения и нажимает `⌘⇧V`.
3. Окно истории открывается поверх текущего приложения, а поиск получает фокус.
4. Пользователь вводит запрос или выбирает запись стрелками.
5. По `Enter` Qipli закрывает окно, возвращается к ранее активному приложению и отправляет вставку выбранного текста.
6. Если целевое приложение не принимает вставку, запись остаётся в истории и может быть выбрана повторно.

### PJ-002 — Последовательно перенести серию

1. Пользователь выделяет значение и нажимает `⌘⇧C`; Qipli начинает или сохраняет текущий Paste Stack, показывает nonactivating panel и отправляет обычный `⌘C` в ещё активное приложение-источник. Полученное копирование становится первым/очередным элементом Stack и History. Пункт status menu Start начинает пустой Stack, поскольку не относится к source selection.
2. Каждое следующее текстовое копирование добавляется в панель и общую историю; повторный `⌘⇧C` не сбрасывает Stack и снова копирует текущее выделение.
3. Пользователь меняет порядок и выбирает прямое или обратное направление.
4. В приложении назначения каждое нажатие `⌘V` передаёт следующий активный элемент.
5. Обработанный элемент остаётся видимым в disabled-состоянии.
6. Ошибочно использованный элемент можно повторно активировать; он становится следующим.
7. После последнего активного элемента режим завершается и панель закрывается.
8. `Esc` или закрытие панели отменяет незавершённый стек, не удаляя его тексты из истории.

## 5. Бизнес-правила

| ID | Правило |
|---|---|
| BR-001 | MVP принимает только элементы с текстовым представлением. Текст, включая Unicode, пробелы, переводы строк, ссылки и код, сохраняется без нормализации содержимого. |
| BR-002 | Одно внешнее изменение буфера с текстом создаёт одну запись истории. Одинаковые события не дедуплицируются ни в истории, ни в активном стеке. |
| BR-003 | Срок хранения считается от последней активности: initial capture или успешно отправленной history paste-команды. Запись с возрастом 30 дней и более не должна показываться пользователю. |
| BR-004 | Paste Stack — временная сессия в памяти. Его элементы ссылаются на копирования текущей сессии, но закрытие стека не управляет жизненным циклом истории. |
| BR-005 | Ручная перестановка задаёт базовый видимый порядок. Прямой обход идёт сверху вниз, обратный — снизу вверх. Изменение порядка и направления гарантируется до первого обработанного `⌘V`. |
| BR-006 | Повторно активированный элемент имеет одноразовый приоритет над текущим следующим; после его повторной обработки обход продолжается с ранее ожидавшего элемента. |
| BR-007 | Qipli может подтвердить обработку сочетания `⌘V`, но не изменение содержимого целевого поля. Поэтому disabled означает «команда вставки отправлена», а не «приложение назначения подтвердило данные». |
| BR-008 | Записи буфера, которые Qipli создаёт сам для истории-вставки или Paste Stack, не порождают новые записи истории и элементы стека. |
| BR-009 | Очистка истории удаляет данные, которыми управляет Qipli, но не очищает текущий системный буфер обмена. |
| BR-010 | Выбранное для вставки значение становится текущим содержимым системного буфера; автоматическое восстановление прежнего содержимого в MVP не выполняется. |

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-001 | Поддерживаемая платформа — macOS 14+; интерфейс и системные интеграции нативные. |
| NFR-002 | Содержимое истории, поиска и стека остаётся на текущем Mac; приложение не требует сети для продуктовых сценариев и не отправляет телеметрию. |
| NFR-003 | Текст не записывается в обычные, диагностические или crash-логи приложения. |
| NFR-004 | Глобальный обработчик клавиатуры не изменяет `⌘V`, когда Paste Stack не активен, и восстанавливается после системного отключения event tap. |
| NFR-005 | Историей можно пользоваться с клавиатуры; текущий выбор, пустое состояние и недоступность вставки визуально различимы. |
| NFR-006 | Отказ хранения, разрешения или системной вставки приводит к видимому состоянию с возможностью повторить действие; приложение не заявляет об успехе молча. |
| NFR-007 | Публичный бинарник подписан Developer ID, использует Hardened Runtime, проходит notarization и проверяется на чистой поддерживаемой macOS. |
| NFR-008 | Тестируемая бизнес-логика отделена от AppKit/Core Graphics адаптеров; автоматические тесты не должны требовать реального содержимого пользовательского буфера. |

## 7. Состояния и ошибки интерфейса

### История

- загрузка локального хранилища;
- пустая история;
- результаты и текущий keyboard selection;
- нет совпадений;
- ошибка чтения/удаления;
- Accessibility-разрешение отсутствует: просмотр и удаление доступны, вставка недоступна с объяснением;
- целевое приложение закрылось или отказалось активироваться: значение остаётся выбранным в истории, показывается ошибка.

### Paste Stack

- пустой активный стек («скопируйте первый текст»);
- сбор элементов;
- готовность к вставке с явным следующим элементом и направлением;
- процесс вставки: pending/next/used-disabled;
- повторно активированный элемент;
- отсутствие разрешения или временно недоступный event tap;
- завершение после последнего элемента;
- отмена пользователем.

## 8. Владение, видимость и приватность

- Все данные принадлежат текущему локальному пользователю macOS и видны любому, кто может работать в этой учётной записи и открыть Qipli.
- В MVP нет дополнительной блокировки, шифрования на уровне приложения и распознавания секретов.
- Пользователь должен до выдачи разрешения увидеть, что история может содержать пароли, токены и другой чувствительный текст.
- Удаление из Qipli не является гарантированным физическим стиранием с SSD и не удаляет копии, уже сохранённые другими приложениями, macOS или Universal Clipboard.

## 9. Наблюдаемые сигналы успеха

- Пользователь завершает PJ-002 без возврата к источнику за каждым значением.
- До первой вставки порядок и направление очевидны и изменяемы.
- Ошибочно обработанный элемент повторно активируется и вставляется следующим.
- Значение из завершённого или отменённого стека находится через PJ-001, пока не истёк срок хранения или пользователь его не удалил.
- Основные сценарии работают без аккаунта и внешней сети.

Числовые продуктовые KPI пока не заданы и не должны выдумываться при реализации.

## 10. Предположения и открытые вопросы

### Видимые предположения

- Qipli оформляется как menu bar utility без постоянного окна и без обязательной иконки в Dock.
- История показывает новые записи первыми; поиск — регистронезависимое вхождение подстроки с системными правилами локали.
- Одинаковые копирования сохраняются как отдельные события и в общей истории, а не только в Paste Stack.
- Управление порядком и направлением блокируется после первого обработанного `⌘V`; восстановление выполняется через повторную активацию.
- Запуск при входе в macOS не включён в MVP; пользователь запускает Qipli сам.

Если проверка прототипа покажет, что любое из этих предположений мешает основному пути, решение нужно записать в [`DECISIONS.md`](DECISIONS.md) и обновить связанные критерии до реализации следующего среза.

### Открытые вопросы, не блокирующие MVP

- Какие сочетания и схема разрешения конфликтов понадобятся для будущей настройки горячих клавиш?
- Нужно ли позднее показывать метаданные приложения-источника? MVP их не сохраняет.
- Нужна ли отдельная команда, одновременно очищающая историю Qipli и текущий системный буфер?
