# Qipli — продуктовый контракт

Статус: согласованный план MVP, публичной поставки и безопасных обновлений

Дата актуализации: 2026-08-26

Источник исходного замысла: [`../PROJECT_BRIEF.md`](../PROJECT_BRIEF.md)

Профиль поставки: `production`. Timebox не задан. Публичный релиз должен быть воспроизводимым, fail-closed и проверенным на реальном обновлении между двумя подписанными версиями.

## 1. Назначение продукта

Qipli — бесплатное open-source приложение для macOS, которое хранит локальную 30-дневную историю текстового буфера обмена и помогает переносить серии значений между приложениями с помощью визуальной очереди Paste Stack.

Основной пользователь — владелец текущей учётной записи macOS. Других ролей, аккаунтов и административного интерфейса в MVP нет.

### Проблема

При последовательном переносе нескольких значений пользователь вынужден многократно переключаться между источником и назначением. Обычная история буфера помогает найти прежнее значение, но не задаёт порядок серии и не даёт удобного восстановления после ошибочной вставки.

### Результат первой версии

Первая версия полезна, когда пользователь может собрать несколько текстовых копирований в одном приложении, проверить их порядок, вставить их по очереди в другом приложении через обычное `⌘V`, восстановить ошибочно использованный элемент и позднее найти любое сохранённое значение в локальной 30-дневной истории.

## 2. Граница MVP

### Обязательно

- нативное приложение для macOS 14 и новее;
- работающий в фоне локальный монитор текстового буфера обмена;
- история текстовых копирований за последние 30 дней;
- окно истории по `⌘⇧V`, поиск, навигация стрелками и вставка по `Enter`;
- удаление отдельной записи и немедленная логическая очистка всей истории Qipli;
- Paste Stack по `⌘⇧C` с панелью поверх других приложений;
- отдельный элемент очереди для каждого события копирования, включая одинаковый текст;
- ручное изменение порядка и прямое/обратное направление;
- последовательная вставка через обычное `⌘V`;
- видимые использованные элементы, их повторная активация и автоматическое завершение;
- отмена незавершённого стека без удаления записей из истории;
- локальная работа без аккаунта, облака, аналитики и передачи содержимого наружу;
- подписанный и notarized релиз через GitHub Releases.

### Ранний post-MVP до первого публичного релиза

- единое окно Settings с текущим состоянием Accessibility и действиями `Allow Access`/`Open System Settings`;
- явный пользовательский переключатель запуска Qipli при входе в macOS;
- переназначение сочетаний History, Start/Collect Paste Stack и Reactivate Previous с безопасным возвратом к значениям по умолчанию;
- опциональный first-run onboarding с объяснением локальной истории и риска чувствительного текста, запросом Accessibility только после пользовательского действия, предложением автозапуска и кратким знакомством с основными возможностями.
- публичный GitHub-репозиторий с unsigned CI для pull request и `main`, понятной лицензией и правилами сообщения об уязвимостях;
- подписанные Developer ID и notarized GitHub Releases, создаваемые защищённым workflow только из версионного тега;
- ручная проверка обновлений и выключенная по умолчанию автоматическая проверка через публичный HTTPS appcast без передачи clipboard/history/search payload.

Эти функции не меняют подтверждённую границу core MVP, но по решениям пользователя от 2026-08-12 и 2026-08-26 должны войти в первый публичный релиз и пройти clean-machine verification в S008.

### Позже

- файлы, изображения и другие медиа;
- сохранение завершённых стеков как повторно используемых наборов.
- beta-channel, phased rollout и delta updates; первый публичный update feed поддерживает один stable channel и полные ZIP.

### Не входит в MVP

- аккаунты, роли и синхронизация между устройствами;
- собственный сервер, сетевой API, телеметрия и облачное резервное копирование; статический appcast и загрузка обновления являются единственным разрешённым продуктовым network path;
- автоматическое распознавание паролей или чувствительных данных;
- гарантированное forensic/secure-стирание байтов с накопителя;
- Mac App Store, монетизация и платные тарифы;
- восстановление незавершённого Paste Stack после перезапуска или аварийного завершения Qipli.
- принудительная тихая установка обновлений без понятного действия или ранее данного согласия пользователя.

## 3. Пользовательские пути

### PJ-001 — Найти и повторно вставить значение

1. Qipli уже запущен и собирает текстовые копирования локально.
2. Пользователь активирует поле назначения и нажимает `⌘⇧V`.
3. Окно истории открывается поверх текущего приложения, а поиск получает фокус.
4. Пользователь вводит запрос или выбирает запись стрелками.
5. По `Enter` Qipli закрывает окно, возвращается к ранее активному приложению и отправляет вставку выбранного текста.
6. Если целевое приложение не принимает вставку, запись остаётся в истории и может быть выбрана повторно.

### PJ-002 — Последовательно перенести серию

1. Пользователь выделяет значение и нажимает `⌘⇧C`; Qipli начинает или сохраняет текущий Paste Stack, показывает nonactivating panel и отправляет обычный `⌘C` в ещё активное приложение-источник. Полученное копирование становится первым/очередным элементом Stack и History. Пункт status menu Start начинает пустой Stack, поскольку не относится к source selection.
2. Каждое следующее текстовое копирование добавляется в панель и общую историю; повторный `⌘⇧C` не сбрасывает Stack и снова копирует текущее выделение.
3. Пользователь меняет порядок и выбирает прямое или обратное направление.
4. В приложении назначения каждое нажатие `⌘V` передаёт следующий активный элемент.
5. Обработанный элемент остаётся видимым в disabled-состоянии.
6. Ошибочно использованный элемент можно повторно активировать действием Reactivate или exact `⌘⇧Z`: shortcut выбирает только последний successfully dispatched occurrence, не вставляет его немедленно и требует следующего обычного `⌘V`. До первой успешной отправки и вне active Stack `⌘⇧Z` остаётся системным Redo.
7. После последнего активного элемента режим завершается и панель закрывается.
8. `Esc` или закрытие панели отменяет незавершённый стек, не удаляя его тексты из истории.

### PJ-003 — Настроить Qipli

1. Пользователь открывает Settings из status menu.
2. В General он видит фактическое состояние Accessibility, может запросить доступ или открыть системные настройки и явно включает или отключает запуск Qipli при входе в macOS.
3. В Shortcuts он меняет сочетания History, Start/Collect Paste Stack и Reactivate Previous либо возвращает их значения по умолчанию.
4. Допустимые изменения применяются без перезапуска Qipli; ошибка регистрации автозапуска или недопустимое сочетание показываются рядом с соответствующей настройкой и не уничтожают последнее рабочее значение.
5. Обычный `⌘V` и `Esc` остаются неизменяемыми системными контрактами Paste Stack.

### PJ-004 — Пройти первый запуск

1. На первом запуске текущего локального профиля Qipli показывает короткий опциональный onboarding до начала чтения pasteboard.
2. Пользователь узнаёт о локальной 30-дневной истории, возможном сохранении чувствительного текста, History и Paste Stack.
3. Accessibility запрашивается только после нажатия явной кнопки; отказ или пропуск не блокирует завершение onboarding и оставляет честное degraded state.
4. Запуск при входе предлагается выключенным по умолчанию и включается только явным выбором пользователя.
5. Пользователь завершает или пропускает onboarding; он больше не открывается автоматически, но доступен повторно из Settings без сброса настроек.

### PJ-005 — Получить новую подписанную версию

1. Пользователь вручную выбирает `Check for Updates…` либо ранее включил автоматическую проверку в Settings.
2. Qipli запрашивает публичный HTTPS appcast, не добавляя clipboard, history или search payload.
3. При наличии более нового совместимого build пользователь видит версию и release notes и явно подтверждает установку.
4. Qipli принимает только update archive с допустимой Sparkle EdDSA signature и ожидаемой Apple code-signing identity.
5. После установки и перезапуска сохраняются локальная история, Settings и Launch at Login; Accessibility перепроверяется и не выдаётся за granted при фактической потере доступа.
6. Offline, invalid feed, download, signature или install failure оставляет текущую версию рабочей и даёт повторить действие позднее.

## 5. Бизнес-правила

| ID | Правило |
|---|---|
| BR-001 | MVP принимает только элементы с текстовым представлением и хотя бы одним непробельным символом. Пустые и состоящие только из Unicode whitespace строки игнорируются; принятый текст, включая Unicode, пробелы, переводы строк, ссылки и код, сохраняется без нормализации содержимого. |
| BR-002 | Одно внешнее изменение буфера с текстом создаёт одну запись истории. Одинаковые события не дедуплицируются ни в истории, ни в активном стеке. |
| BR-003 | Срок хранения считается от последней активности: initial capture или успешно отправленной history paste-команды. Запись с возрастом 30 дней и более не должна показываться пользователю. |
| BR-004 | Paste Stack — временная сессия в памяти. Его элементы ссылаются на копирования текущей сессии, но закрытие стека не управляет жизненным циклом истории. |
| BR-005 | Ручная перестановка задаёт базовый видимый порядок. Прямой обход идёт сверху вниз, обратный — снизу вверх. Изменение порядка и направления гарантируется до первого обработанного `⌘V`. |
| BR-006 | Повторно активированный элемент имеет одноразовый приоритет над текущим следующим; после его повторной обработки обход продолжается с ранее ожидавшего элемента. `⌘⇧Z` повторно активирует только последнее successfully dispatched exact occurrence, повторяется идемпотентно до следующей успешной отправки и никогда не является undo в приложении назначения. |
| BR-007 | Qipli может подтвердить обработку сочетания `⌘V`, но не изменение содержимого целевого поля. Поэтому disabled означает «команда вставки отправлена», а не «приложение назначения подтвердило данные». |
| BR-008 | Записи буфера, которые Qipli создаёт сам для истории-вставки или Paste Stack, не порождают новые записи истории и элементы стека. |
| BR-009 | Очистка истории удаляет данные, которыми управляет Qipli, но не очищает текущий системный буфер обмена. |
| BR-010 | Выбранное для вставки значение становится текущим содержимым системного буфера; автоматическое восстановление прежнего содержимого в MVP не выполняется. |
| BR-011 | Настраиваются только три Qipli-команды: History, Start/Collect Paste Stack и Reactivate Previous. Обычный `⌘V` и `Esc` не настраиваются; новое сочетание не может совпадать с другой Qipli-командой или защищённым input contract. Приложение не обещает обнаруживать все конфликты с другими программами macOS. |
| BR-012 | Последнее допустимое сочетание остаётся активным при ошибочном вводе или повреждённом сохранённом значении; недоступное сохранённое значение заменяется документированным default с видимым состоянием восстановления. |
| BR-013 | Автозапуск всегда opt-in: onboarding не предвыбирает согласие, Settings отображает фактический системный status, а отказ регистрации или внешнее отключение в System Settings не выдаются за успех. |
| BR-014 | Onboarding показывается автоматически один раз для текущего локального профиля. Finish, Skip или явное закрытие считаются завершением; аварийное завершение до этого не считается. Повторный запуск из Settings не сбрасывает completion, shortcuts, Accessibility или login-item state. |
| BR-015 | `CFBundleShortVersionString` соответствует stable tag без префикса `v`, а `CFBundleVersion` является числовым и строго возрастает для каждого опубликованного update. Несовпадение tag, version или build завершает release workflow ошибкой до подписи и публикации. |
| BR-016 | Код из pull request, fork или обычного push не получает signing, notarization или Sparkle private keys. Release secrets доступны только защищённому tag workflow после разрешённого environment gate. |
| BR-017 | Update feed публикуется только после успешной подписи, notarization, повторной проверки скачанного asset и наличия стабильного публичного URL. Feed не указывает на draft, failed или заменённый artifact. |
| BR-018 | Ручная и автоматическая проверка обновлений используют один updater contract. Отказ сети, feed, EdDSA, Apple signature или install не изменяет установленную рабочую версию и не блокирует локальные History/Paste Stack сценарии. |

## 7. Состояния и ошибки интерфейса

### История

- загрузка локального хранилища;
- пустая история;
- результаты и текущий keyboard selection;
- нативный title bar — единственный заголовок History; Search и Clear All находятся в одной верхней строке, а видимой нижней кнопки Paste нет: Enter и double-click выбранной exact occurrence остаются способами вставки; Search использует compact neutral system shell без меняющегося blue focus outline, но сохраняет native caret/focus и VoiceOver hint для фильтра и Up/Down selection;
- удаление конкретной occurrence доступно отдельной нативной кнопкой с символом `trash`, доступным именем и help «Delete»; при пустом Search и выбранной occurrence локальный `⌫`/Delete удаляет только эту occurrence, а при непустом Search остаётся обычным text editing и ничего не удаляет из history; выделенная строка имеет ненавязчивую rounded surface и outline системного accent color, не конкурируя с Search shell;
- нет совпадений;
- ошибка чтения/удаления;
- Accessibility-разрешение отсутствует: просмотр и удаление доступны, вставка недоступна с объяснением;
- целевое приложение закрылось или отказалось активироваться: значение остаётся выбранным в истории, показывается ошибка.

### Paste Stack

- пустой активный стек («скопируйте первый текст»);
- сбор элементов;
- готовность к вставке с явным следующим элементом и направлением;
- borderless edge-to-edge panel использует один custom header: доступный Close слева, единственный заголовок Paste Stack по центру и direction toggle справа; List является основной поверхностью без внешних window paddings;
- compact direction icon toggle показывает `arrow.down` для direct/top-to-bottom и `arrow.up` для reverse/bottom-to-top, меняет только direction через существующий deferred intent и disabled после traversal lock; его доступные label/value/hint сообщают текущее направление и результат toggle;
- pending rows при доступном reorder сохраняют native drag и получают только decorative drag handle; VoiceOver получает Move Up/Move Down actions с теми же UUID и bounds, а next row отличима не только цветом — compact icon plus subtle rounded system-accent surface;
- процесс вставки: pending/next/used-disabled;
- повторно активированный элемент;
- отсутствие разрешения или временно недоступный event tap;
- завершение после последнего элемента;
- отмена пользователем.

### Accessibility Permission

- native title bar — единственный заголовок Permission panel; content содержит ровно одно краткое status sentence и одну релевантную кнопку без дублирующего menu description;
- `notRequested`: «Enable Accessibility for global shortcuts and paste.» и `Allow Access`, который запрашивает существующее системное разрешение;
- `denied`: «Accessibility access is off.» и `Open System Settings`;
- `granted`: «Accessibility access is enabled.» и `Open System Settings` для управления или отзыва разрешения;
- панель компактна, но сохраняет native close, system material, nonactivation и Spaces/full-screen contracts.

### Settings

- singleton active window с разделами General и Shortcuts;
- Accessibility: `notRequested`, `denied`, `granted` и временно unavailable с теми же честными действиями, что существующая Permission panel;
- Launch at Login: off, enabled, requires approval и retryable error; при необходимости доступно открытие системного раздела Login Items;
- Shortcut recorder: idle, recording, valid, internal/protected conflict и recovered-default; invalid input не заменяет последнее рабочее сочетание;
- Reset to Defaults восстанавливает только три shortcuts и не меняет Accessibility, launch-at-login или onboarding completion;
- действие `Show Onboarding Again` открывает onboarding без сброса текущих настроек.

### First-run onboarding

- короткий опциональный flow без обязательной кастомизации;
- privacy/value explanation виден до старта pasteboard monitor;
- Accessibility prompt появляется только после явного действия пользователя; Skip/отказ доступны;
- Launch at Login выключен по умолчанию и включается только явным действием;
- default shortcuts и ключевые возможности объясняются даже без разрешения;
- Finish, Skip и close завершают one-time flow; crash/force quit до сохранения completion приводит к повторному показу.

### Updates

- `idle`: текущая версия работает, сетевой запрос не выполняется;
- `checking`: видимый progress только после ручного действия или сохранённого opt-in;
- `upToDate`: ручная проверка сообщает, что новой совместимой версии нет;
- `available`: показаны новая версия, release notes и действие установки;
- `downloading`/`installing`: прогресс можно понять без раскрытия технических secrets;
- `offline`/`invalidFeed`/`invalidSignature`/`installFailed`: текущая версия остаётся рабочей, ошибка видима и retryable;
- `relaunchRequired`: пользователь явно завершает установку и перезапуск.

## 8. Владение, видимость и приватность

- Все данные принадлежат текущему локальному пользователю macOS и видны любому, кто может работать в этой учётной записи и открыть Qipli.
- В MVP нет дополнительной блокировки, шифрования на уровне приложения и распознавания секретов.
- Пользователь должен до начала чтения pasteboard и до выдачи разрешения увидеть, что история может содержать пароли, токены и другой чувствительный текст.
- Удаление из Qipli не является гарантированным физическим стиранием с SSD и не удаляет копии, уже сохранённые другими приложениями, macOS или Universal Clipboard.
- Публичный update host видит обычный HTTPS-запрос и сетевой адрес клиента. Qipli не добавляет в update request clipboard, history, search, preview, account или device identifier.
- Автоматическая проверка обновлений выключена до явного opt-in и отключается без потери локальных функций.

## 9. Наблюдаемые сигналы успеха

- Пользователь завершает PJ-002 без возврата к источнику за каждым значением.
- До первой вставки порядок и направление очевидны и изменяемы.
- Ошибочно обработанный элемент повторно активируется и вставляется следующим.
- Значение из завершённого или отменённого стека находится через PJ-001, пока не истёк срок хранения или пользователь его не удалил.
- Основные сценарии работают без аккаунта и внешней сети.
- Пользователь после первого запуска понимает default hotkeys и может позднее изменить их, проверить разрешение или изменить автозапуск в одном Settings window.
- Публичный tag создаёт один однозначный подписанный release artifact, а установленная предыдущая версия обнаруживает его и обновляется без потери локальных данных и настроек.

Числовые продуктовые KPI пока не заданы и не должны выдумываться при реализации.

## 10. Предположения и открытые вопросы

### Видимые предположения

- Qipli оформляется как menu bar utility без постоянного окна и без обязательной иконки в Dock.
- История показывает новые записи первыми; поиск — регистронезависимое вхождение подстроки с системными правилами локали.
- Одинаковые копирования сохраняются как отдельные события и в общей истории, а не только в Paste Stack.
- Управление порядком и направлением блокируется после первого обработанного `⌘V`; восстановление выполняется через повторную активацию.
- Core MVP не зависит от запуска при входе, настраиваемых hotkeys или onboarding; они входят в первый публичный релиз как ранний post-MVP setup layer.
- Первый публичный релиз включает Sparkle, один stable update channel, ручную проверку и выключенные по умолчанию фоновые проверки. Beta channels, delta updates и phased rollout остаются на потом.

Если проверка прототипа покажет, что любое из этих предположений мешает основному пути, решение нужно записать в [`DECISIONS.md`](DECISIONS.md) и обновить связанные критерии до реализации следующего среза.

### Открытый вопрос, блокирующий публичный переход

- Какую open-source лицензию выбрать для Qipli? До ответа S014 не меняет видимость репозитория и не публикует первый stable release.

### Открытые вопросы, не блокирующие MVP

- Нужно ли позднее показывать метаданные приложения-источника? MVP их не сохраняет.
- Нужна ли отдельная команда, одновременно очищающая историю Qipli и текущий системный буфер?
